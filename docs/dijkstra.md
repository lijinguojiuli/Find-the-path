# Dijkstra：用优先队列寻找最短路径

以下保留最初单位成本阶段的教学与验收记录。当前已支持地形进入成本，网页也已接入搜索和移动，
最新规则与教程见 [第 7–10 天说明](simulation.md)。

本阶段所有可通行格子的单步成本固定为 1，只允许上、右、下、左移动。
算法模块不依赖 Pygame，不修改地图，也没有接入网页或桌面界面。

## 调用与统一结果

```python
from robot_path_lab.algorithms import SearchResult, bfs, dijkstra
from robot_path_lab.grid import Grid

grid = Grid(3, 3, start=(0, 0), goal=(2, 0), obstacles={(1, 0), (1, 1)})
first = bfs(grid)
second = dijkstra(grid)

assert type(first) is type(second) is SearchResult
assert first.found and second.found
assert len(first.path) - 1 == len(second.path) - 1 == 6
```

两种算法都返回 `SearchResult`：

- `found`：是否找到路径。
- `path`：包含起终点的节点元组；不可达时为空元组。
- `visited_order`：有效出队并处理的节点顺序，包含起点及被取出的终点。
- `visited_count`：`len(visited_order)`，不计尚未处理的待探索节点或过期堆条目。

原有 `BFSResult` 保留为 `SearchResult` 的兼容别名，旧导入仍可使用。
同起终点返回单节点路径、0 步、访问 1；缺少端点时抛出 `ValueError`，与不可达区分。
`iter_dijkstra(grid)` 与 BFS 一样在调用时捕获快照，每次迭代产出一个处理节点，最终返回结果。

## 三种数据结构各做什么

### 距离数组

`distances[y][x]` 保存起点到 `(x, y)` 当前已知的最小成本。起点初始化为 0，其他格子为无穷大。
无穷大表示尚未发现可达路线，不代表格子本身是障碍。

处理当前格子时，计算 `candidate_distance = distance + 1`。
只有它比邻居已有距离更小时才更新，这一步称为“松弛”，也就是改进已知距离。
各行用独立列表创建，避免修改一行意外影响其他行。

### 前驱节点

`parents[neighbor] = current` 记录更短路线从哪个格子走来。
只在距离改善时更新；找到终点后沿前驱走回起点，再反转得到正向路径。
路径回溯复用公共函数，不在 Dijkstra 中复制 BFS 的整套代码。

### 优先队列

使用 `heapq` 最小堆维护 `(距离, 入队序号, 节点)`，每次取出当前已知距离最小的节点。
入队序号在距离相同时保留稳定的处理顺序，不会改变距离优先原则。
若堆条目的旧距离已被更短距离替代，就跳过它，不计访问数。

当弹出终点时即可返回；队列耗尽且未遇到终点时返回不可达。
非负边成本下，这个“先处理最小距离”的原则保证节点被正式处理时的距离已经最优。
当前每步成本均为 1，因此最小成本也等于最少步数。

## 与 BFS 的实际对照

下表中的步数来自相同 `Grid` 上实际调用两个算法，不是推测结果。

| 地图 | BFS 步数 | Dijkstra 步数 |
| --- | --- | --- |
| 1×5 直线 | 4 | 4 |
| 3×4 无障碍矩形 | 5 | 5 |
| 3×3 绕行地图 | 6 | 6 |
| 3×5 障碍墙留缺口 | 8 | 8 |
| 完整障碍墙阻断 | 无路径 | 无路径 |
| 起终点相同 | 0 | 0 |

此外，测试在 3×3 地图固定起终点，穷举其余七格的全部 128 种障碍布局，
比较可达性与最短路径长度，并检查 Dijkstra 路径的邻接性、边界和障碍合法性。

## 复用范围

`common.py` 提供统一结果、不可变地图快照、四邻域遍历、路径回溯和步进结果收集。
BFS 继续使用 FIFO 队列及首次发现标记；Dijkstra 独立使用距离数组、松弛与最小堆。
没有引入包含算法模式分支的通用搜索框架。

普通堆实现的时间复杂度为 O((V+E) log V)，网格中可写为 O(V log V)，辅助空间 O(V)。
单位成本时 BFS 更简单；本阶段没有提供不同地形成本或负成本输入接口。
