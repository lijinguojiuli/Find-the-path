# 迷宫布局与响应优化

本阶段处理三个实际反馈：墙格出现空心观感、操作等待偏长、讲解区挤占地图。只修改独立迷宫网页，不改变算法规则或原实验台。

## 布局与操作

- 顶部集中地图类型、推荐对比、换图和地图设置。设置作为覆盖面板展开，不把地图往下推。
- 工作区上方只保留展示模式、算法与开始/取消计算；地图先于播放和视图控制显示。
- 播放、暂停、单步、速度及重播/最终结果位于地图下方。
- 节点讲解与学习提示在宽屏侧栏显示；窄窗口放在地图之后，展开讲解不改变地图的位置和高度。
- 664×702 与 390×844 窗口均检查了横向溢出。字号保持可读，不以缩小整个页面解决布局问题。
- 大屏模式仍只修改网页布局，不调用原生全屏。

参考了 [VisuAlgo 图遍历](https://visualgo.net/en/dfsbfs) 的独立播放控制、可收起状态/代码面板，以及 [Red Blob Games A* 教程](https://www.redblobgames.com/pathfinding/a-star/introduction.html) 中交互图与解释配合的方式。保留本项目中文、浅色教学界面和深色地图。

## 为什么响应更快

原普通搜索与实验对比共用同一流程：热身 1 次、计时 5 次、再收集 1 次教学记录，首次播放前共执行 7 次搜索。现在普通搜索执行一次带教学记录的搜索；只有明确选择对比或多场景实验时才重复采样。

普通搜索显示「单次计算，含讲解记录」，实验结果显示中位数；表格逐行标注，不把两种耗时混在同一口径下排名。两者都排除地图复制、消息和动画。

完成任务后的 Worker 保留供下一个任务使用，减少模块启动；若有未完成任务需要取消或换图，仍终止旧 Worker，并检查请求号、地图版本，防止旧结果覆盖新地图。风格图鉴也复用同种子的已完成预览。

地图所有缩放级别使用不透明栅格填色，每个墙格完整填满。探索推进时增量改写栅格，纯光效帧不重新创建墙体几何或重复上传未变化的图像。节点访问位置建立一次索引，讲解刷新做节流，光效帧不重复重建讲解 DOM。

## 实际验证（2026-10-18）

- Python 全套：**1047 passed，7.81 秒**。
- 网页全套：**385 passed，0 failed，0 skipped**，约 1.92 秒。
- 两项回归测试在修复前失败：放大散墙未使用完整格子填充；普通搜索调用计时时钟 10 次而非单次的 2 次。修复后通过。
- 新增页面结构测试：控件和画布都在工作区内，讲解位于独立侧栏，播放控件位于地图后，HTML 标签闭合且 ID 唯一。
- 浏览器发现滚动后地图会因视口位置改变而自行增高，改为考虑页面滚动偏移，并增加高度稳定的回归测试。
- 检查长访问记录的节点讲解在暂停回退、切换算法后归属正确，保留原有搜索和播放断言。

浏览器实际检查了普通搜索、暂停、单步、推荐双算法对比及五次采样标识；百万格地图的全部算法比较可取消，取消后可以重新生成与搜索；大屏状态下原生全屏元素为空，控制台无错误。664×702 窗口展开讲解前后，地图顶部均约 201 px、高度约 299 px，没有横向溢出。390×844 窗口中地图顶部约 201 px、高度约 374 px，没有横向溢出。尺寸按本机浏览器实际布局记录，不作跨设备像素承诺。

### 计算流程实测

`scripts/maze-response-audit.mjs` 在同一地图交替测量旧普通搜索流程和新流程，各取三次墙钟时间的中位数；所有结果成本一致。Node v24.19.0，本机记录：

| 地图 | 算法 | 原流程/ms | 单次流程/ms |
| --- | --- | ---: | ---: |
| 301×301 不规则散墙 | A* | 112.39 | 20.98 |
| 1001×1001 不规则散墙 | BFS | 601.14 | 95.76 |
| 1001×1001 带环路 | A* | 1082.48 | 177.47 |

这是 Node 计算流程总时间，包含各自执行的教学记录，排除浏览器 Worker 启动、消息传输、绘图和网络。不能把表中数值视为用户点击到屏幕响应的完整时间，也不表示所有设备都有同样倍数提升。正确性测试没有耗时阈值。
