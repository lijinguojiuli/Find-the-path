算法使用地图快照，不依赖 Pygame；搜索结果尚未接入网站或桌面界面。

## 调用与统一结果

```python
from robot_path_lab.algorithms import SearchResult, astar, dijkstra
from robot_path_lab.grid import Grid

grid = Grid(3, 3, start=(0, 0), goal=(2, 0), obstacles={(1, 0), (1, 1)})

baseline = dijkstra(grid)

assert type(result) is type(baseline) is SearchResult

assert len(result.path) - 1 == len(baseline.path) - 1 == 6
print(result.path)
print(result.visited_order, result.visited_count)
```

三种算法都返回已有的 `SearchResult`：

- `found`：是否找到路径。
- `path`：从起点到终点的节点元组，包含两个端点；不可达时为空。
- `visited_order`：有效出队并处理的节点顺序，包含起点和被取出的终点。
- `visited_count`：处理节点数，不计仍在堆中等待的节点或过期条目。

路径步数为 `len(path) - 1`，仅在找到路径时计算；不可达不能显示为 -1 步。
起终点相同返回单节点路径、0 步、访问 1；缺少端点时抛出中文 `ValueError`。
非法尺寸、越界端点和端点被障碍覆盖等输入继续由 `Grid` 拒绝。

`iter_astar(grid)` 在调用时立即捕获快照，逐次产出处理节点，
最终结果由生成器的 `StopIteration.value` 返回。`astar(grid)` 复用公共收集函数得到完整结果。
提供迭代入口不等于已经实现界面动画。

## g、h 和 f 各做什么

`g_scores[y][x]` 保存从起点到该格当前已知的最小实际代价：起点为 0，其余为无穷大。
找到邻居的新候选路线时，计算 `candidate_g = current_g + 1`；
只有候选更小时才更新 `g` 和 `parents`。`parents` 保存这条更短路线的前驱，供最终回溯。

`h(n) = abs(x - goal_x) + abs(y - goal_y)` 是曼哈顿距离，估计该格到终点还需要多少代价。
`f(n) = g(n) + h(n)` 合并已走部分与剩余估计。

`heapq` 最小堆条目为 `(f, h, 入队序号, g, 节点)`，始终先取最小 `f`。
仅当 `f` 相等时优先较小 `h`，之后用入队序号保持结果可复现；这不会改变 `f` 优先原则。
如果取出的旧 `g` 与当前最小记录不同，就跳过该过期条目。
只有终点从堆中被有效取出时才结束，不能在首次把终点加入队列时就返回。

## 为什么曼哈顿距离合理

四方向移动时，每步只能把横向差或纵向差减少 1。
因此从任意格到终点，至少要走 `横向差 + 纵向差` 步。
没有障碍时恰好能用这么多步到达；障碍可能迫使绕路，不能让所需步数变少。
所以 `h` 永远不会高估真实的最低剩余代价，这称为**可采纳性**。

它还满足**一致性**：对任意相邻可通行格 `n` 和 `n'`，
`h(n) <= 1 + h(n')`，且终点的 `h` 为 0。
结合正确的 `g` 更新与最小堆搜索，可以在有效弹出终点时得到最短路。
当前成本全部为 1，因此最低成本与最少步数相同。

## 什么情况下最优性可能失效

- 估值过大，例如把曼哈顿距离乘以 2，可能让实际更短的路线过晚才被考虑。
- 如果未来允许成本为 1 的对角移动，横纵各差 1 的目标只需 1 步，曼哈顿估值却为 2，会高估。
- 如果未来某些进入成本低于 1，未经缩放的曼哈顿距离也可能高估；
  四方向加权地图可用“最小单步成本 × 曼哈顿距离”作为下界。
- 对可采纳但不一致的其他启发式，如果实现永久关闭节点且不允许更短路线重新打开节点，
  也可能失去最优性。当前固定曼哈顿启发式具有一致性。

高估意味着不再保证最优，并不表示每张地图都会出错。
如果未来成本都不低于 1，原曼哈顿距离仍是下界；不能仅因存在高成本地形就断言它失效。
本阶段没有增加这些移动规则、地形输入或自定义启发式接口。
