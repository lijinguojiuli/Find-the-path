# BFS 广度优先搜索

当前网站已接入搜索播放与移动，支持地形成本，完整操作见 [第 7–10 天说明](simulation.md)。
BFS 仍优化步数，新增 total_cost 报告其路线的实际成本，不保证加权总代价最低。

## 接口

结果已统一为 `SearchResult`；原有 `BFSResult` 名称保留为兼容别名，原有字段与行为保留。

```python
from robot_path_lab.algorithms import bfs
from robot_path_lab.grid import Grid

grid = Grid(3, 3, start=(0, 0), goal=(2, 0), obstacles={(1, 0), (1, 1)})
result = bfs(grid)

assert result.found
assert result.path == ((0, 0), (0, 1), (0, 2), (1, 2), (2, 2), (2, 1), (2, 0))
assert result.visited_count == 7
```

- `found`：是否找到路径。
- `path`：包含起点和终点的路径节点元组；不可达时为空元组。
- `visited_order`：节点出队并处理的顺序，包含起点和被处理的终点，每个节点最多一次。
- `visited_count`：`len(visited_order)`，仅入队但尚未处理的节点不计数。
- 成功路径的步数是 `len(path) - 1`；访问数和路径步数不是同一个指标。
- 未设置起点或终点是非法输入，抛出 `ValueError`；合法但不可达的地图返回 `found=False`。

起终点相同时路径只有一个节点，步数为 0，访问数为 1。
搜索开始时复制起终点、尺寸和障碍快照，不修改原地图。

## 实际运行的小地图

`S` 为起点，`G` 为终点，`#` 为障碍，`.` 为空地，`B` 为起终点重合。
表中的 `/` 表示换行。以下结果来自真实调用 `bfs()`，也是 pytest 中的已知答案案例。

| 地图 | 找到路径 | 最短步数 | 访问数 |
| --- | --- | --- | --- |
| `S...G` | 是 | 4 | 5 |
| `S#G / .#. / ...` | 是 | 6 | 7 |
| `S.#.G / ..#.. / .....` | 是 | 8 | 13 |
| `S#G / .#. / .#.` | 否 | 无路径 | 3 |
| `B` | 是 | 0 | 1 |

绕行地图的路径从左上走到底部，再从右侧回到右上角：

```text
S#G
.#.
...
```

还测试了矩形地图、单列地图、相邻终点、多条最短路径、禁止斜向穿角、
1500 步长路径、重复搜索与没有第三方包时的算法运行。

## 为什么保证最短路径

`deque` 是先进先出队列。从起点开始，先处理距离为 0 的节点，再处理距离为 1 的节点，
然后是距离为 2、3……的节点。处理距离为 k 的节点时，新发现的邻居放到队尾，
因此不会越过尚未处理的较近节点。

节点在第一次入队时就记录父节点并标记为已发现。第一次到达它的路线具有最少步数，
后续更长的路线不会覆盖这个父节点。找到终点后，沿父节点回溯并反转，就得到从起点到终点的最短路径。

当每步代价都相同时，总代价等于“步数 × 单步代价”，所以最少步数也意味着最低总成本。
不同地形具有不同成本时，BFS 不保证最低成本，本阶段不实现加权搜索。

固定邻居顺序是上、右、下、左。因此多条路线同样短时，结果仍可复现。
时间复杂度 O(V+E)，四邻域网格中为 O(行数×列数)；辅助空间 O(V)。

## 步进入口

`iter_bfs(grid)` 在调用时捕获地图快照，每次 `next()` 产出一个已处理节点。
完成时的 `StopIteration.value` 是同样的 `BFSResult`。普通调用直接使用 `bfs()`。
算法不包含绘制、延时、文件操作或界面事件；这一步进接口尚未接入网页或桌面界面。
