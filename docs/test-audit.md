## 固定种子与参考答案

使用种子 `0、7、42、20261018`，每个测试使用独立随机数生成器，不修改全局随机状态。

- 普通随机地图：每个种子 75 张，共 300 张，尺寸 1–18 行/列。
  混合无障碍、不同障碍密度、相同端点、单行/单列、单位成本、全高成本和混合成本。
- 独立参考：每个种子 10 张小地图，共 40 张，尺寸不超过 5×5。
  测试中的 Bellman-Ford 不复用生产代码的优先队列、启发式或邻居生成函数。
- 动态重规划：每个种子 25 张，共 100 张，包含路径外障碍、剩余路径阻断、加权绕行和强制完整墙阻断。
  检查新路径从当前位置开始，与 Dijkstra 最低成本一致，且失败时不会继续旧路径。
- 网页：每个种子 20 张，共 80 张，分别验证算法代价与已有内存快照恢复。

BFS 只对照可达性与路径合法性；加权地图不要求 BFS 达到最低成本。
均匀成本地图上额外要求 BFS 与最优成本一致。
测试不比较不同算法必须返回同一条路线，因为可能存在多条等价最优路线。
随机测试不能代替最短路正确性的数学证明，因此同时保留已知答案、穷举与独立参考实现。

## 已确认并修复的 Bug

问题：重规划准备过程中发现地图没有终点时，独立控制器没有清理异常状态。
首次请求会留下 `replanning`；替换已有请求时，还可能残留旧的 pending 请求。
网页界面已有部分错误处理，但核心 API 本身不能依赖界面替它清理。

复现顺序：创建有效地图及机器人，移动至中间位置，可选地发起一个待完成请求；
通过已有 `Grid.set_goal(None)` / `setGoal(null)` 清除终点，然后再次请求重规划。
修复前 Python 会抛出错误但状态残留；网页直接请求还会生成缺少终点的无效快照。

修改仅涉及两个生产模块：

- `src/robot_path_lab/replanning.py`：快照构建失败时调用既有 fail()，清除 pending 并原地停止，再重新抛出原错误。
- `web/replanning.mjs`：拒绝缺少终点的请求；准备阶段失败时做相同清理并保留错误。

每侧 4 项回归保持严格断言：必须报错、pending 必须为空、状态必须 blocked、只能保留当前格、
再次开始也不能移动，并验证恢复合法终点后仍可正常重规划。
没有修改 BFS、Dijkstra、A* 的算法逻辑，没有新增界面或保存加载功能。
